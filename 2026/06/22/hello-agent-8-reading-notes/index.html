面试速记

背诵版总结

第八章的核心是给 HelloAgents 框架补上两个关键能力：记忆系统 Memory 和 检索增强生成 RAG。前面的章节已经实现了 Agent 的基础架构、范式和工具调用，但如果智能体没有记忆，就无法记住用户偏好、历史交互和长期经验；如果没有检索，就只能依赖模型训练时的静态知识，容易出现知识过时、专业知识不足和幻觉问题。因此，本章从认知科学中的人类记忆系统出发，将智能体记忆划分为工作记忆、情景记忆、语义记忆和感知记忆，并通过 MemoryTool 与 MemoryManager 实现记忆的添加、搜索、整合、遗忘和统计。同时，本章还实现了 RAGTool，把外部文档通过 MarkItDown 转成 Markdown，再进行结构化分块、嵌入向量化、向量数据库存储和高级检索，最终让 Agent 能基于外部知识生成更可靠的答案。最后，本章通过智能文档问答助手案例，把 MemoryTool 和 RAGTool 结合起来，实现 PDF 加载、文档问答、学习笔记、学习回顾和报告生成，展示了记忆与检索如何让智能体从“单轮问答工具”升级为“能长期学习和利用知识的助手”。

面试表达模板

如果面试官问“Agent 为什么需要记忆和检索”，可以这样回答：

我理解记忆和检索是 Agent 从简单问答走向长期任务执行的关键能力。LLM 本身通常是无状态的，每次调用之间不会自动记住用户信息，所以需要 Memory 系统保存当前对话、历史事件、用户偏好和抽象知识。第八章中把记忆分成工作记忆、情景记忆、语义记忆和感知记忆，分别对应短期上下文、具体交互事件、长期知识规则和多模态信息。另一方面，LLM 的内置知识是静态的，存在时效性和专业领域不足的问题，所以需要 RAG 系统从外部知识库检索相关内容，再注入 Prompt 生成答案。HelloAgents 通过 MemoryTool 管理记忆生命周期，通过 RAGTool 完成文档解析、分块、向量化、检索和问答。二者结合后，Agent 不仅能回答当前问题，还能记住用户历史、积累学习经验，并基于外部文档生成更可靠的回答。

高频面试问题

1. Memory 和 RAG 的区别是什么？

Memory 主要解决的是“智能体能不能记住过去”的问题，保存用户偏好、历史交互、学习经历和长期知识；RAG 主要解决的是“智能体能不能利用外部知识”的问题，通过检索外部文档或知识库来增强回答。简单说，Memory 偏个体经验和长期状态，RAG 偏外部知识和事实依据。

2. 为什么 LLM 本身不等于有记忆？

因为大多数 LLM API 调用是无状态的。模型每次只根据当前输入和传入的上下文生成答案，不会自动保存上一次对话内容。即使上下文窗口里有历史消息，窗口也有长度限制，早期信息可能被截断。因此，Agent 需要额外的记忆模块来持久化重要信息。

3. 四种记忆类型分别是什么？

  • 工作记忆：保存当前会话的临时上下文，访问快、容量小、生命周期短。
  • 情景记忆：保存具体事件和交互经历，适合学习历程回顾和经验复盘。
  • 语义记忆：保存抽象知识、概念、规则和用户长期偏好，适合长期推理。
  • 感知记忆：保存图像、音频等多模态信息，支持跨模态检索。

4. MemoryTool 的核心操作有哪些？

MemoryTool 提供统一接口，常见操作包括：add 添加记忆、search 搜索记忆、summary 获取摘要、forget 选择性遗忘、consolidate 记忆整合、update 更新记忆、remove 删除记忆、stats 查看统计信息。

5. RAG 的基本流程是什么？

RAG 一般分为两个阶段：数据准备阶段和应用问答阶段。数据准备阶段包括文档解析、文本分块、向量化和存储；应用阶段包括用户提问、查询向量化、检索相关片段、构建上下文、调用 LLM 生成答案。

6. MQE 和 HyDE 分别解决什么问题？

MQE 多查询扩展解决的是“用户表述和文档表述不一致”的问题，它用多个等价查询提高召回率。HyDE 解决的是“问题和答案在语义空间中不匹配”的问题，它先生成一个假设答案，再用假设答案去检索真实文档。

Hello-Agents 第八章：记忆与检索阅读笔记

1. 本章核心内容

第八章《记忆与检索》的主题是：让智能体拥有长期记忆能力和外部知识检索能力。

在前面的章节中，HelloAgents 已经具备了基础框架、工具系统和多种 Agent 范式，但它仍然缺少两个关键能力：

  1. 记忆系统 Memory System：让智能体记住历史交互、用户偏好和长期经验。
  2. 检索增强生成 RAG：让智能体从外部知识库中检索信息，辅助生成更准确的回答。

这两个能力分别对应 Agent 的两类核心需求：

如果没有 Memory，Agent 每次对话都像第一次见到用户，无法保持连续性；如果没有 RAG，Agent 只能依赖模型训练时的静态知识，难以处理最新信息、私有文档和专业知识。

2. 为什么 Agent 需要记忆与检索？

2.1 LLM 的无状态问题

大语言模型本身通常是无状态的。也就是说，每次 API 调用都是一次独立计算，模型不会自动保存上一次对话的信息。

这会带来几个问题：

  • 上下文丢失：长对话中，早期信息可能被上下文窗口截断；
  • 个性化不足：模型无法稳定记住用户偏好、习惯和长期目标；
  • 学习能力受限：无法从历史成功或失败中积累经验；
  • 一致性问题：多轮对话中可能前后矛盾。

因此，Agent 需要独立的 Memory 系统，将重要信息持久化保存，并在需要时检索出来。

2.2 LLM 的静态知识问题

LLM 的知识主要来自训练数据，存在天然局限：

  • 训练数据有时间截止点，知识可能过时；
  • 通用模型对专业领域知识掌握不够深入；
  • 容易生成看似合理但并不准确的幻觉内容；
  • 缺少可追溯的信息来源。

RAG 的作用就是在生成回答前，先从外部知识库中检索相关内容，再把检索结果作为上下文提供给模型，从而提高回答的准确性、时效性和可解释性。

3. 从认知科学理解智能体记忆

本章首先借鉴人类记忆系统，将智能体记忆设计成分层结构。

人类记忆一般可以分为：

人类记忆类型 特点 Agent 中的对应设计
感觉记忆 时间极短，保存感官输入 感知记忆
工作记忆 短期、容量有限，服务当前任务 工作记忆
长期记忆 持久保存知识和经历 情景记忆、语义记忆

这种设计思路说明：Agent 的记忆不应该只是简单保存聊天记录，而应该根据不同信息的生命周期、重要性和用途进行分层管理。

9.2 HyDE：假设文档嵌入

HyDE 的全称是 Hypothetical Document Embeddings。

它的核心思想是：

传统检索是用“问题”匹配“文档”，但问题通常是疑问句，文档通常是陈述句，二者在语义空间中可能不够接近。

HyDE 会先让 LLM 写一段可能的答案，再用这段“假设答案”的向量去检索真实文档。即使假设答案不完全正确，它也可能包含关键术语和领域表达，从而提高检索效果。

  • 用户提问历史；
  • 文档加载事件；
  • 学习笔记；
  • 概念知识。

系统可以基于用户历史生成学习报告，统计：

  • 加载文档数量；
  • 提问次数；
  • 笔记数量；
  • 当前学习文档；
  • 记忆摘要；
  • RAG 知识库状态。

这个案例中，RAGTool 和 MemoryTool 各司其职：

例如：

  • 用户加载 PDF：RAGTool 负责解析和索引，MemoryTool 记录“加载了某文档”；

11. 本章对 Agent 开发的启发

11.1 Agent 不能只依赖上下文窗口

上下文窗口只能暂时保存信息，不能替代长期记忆。真实 Agent 需要把重要信息写入外部存储，并在需要时检索回来。

11.2 记忆需要生命周期管理

记忆不是越多越好。如果不做遗忘和整合，系统会出现存储膨胀、检索噪声增加、隐私风险变高等问题。因此要设计：

  • 重要性评分；
  • 时间衰减；
  • 容量限制；
  • 选择性遗忘；
  • 记忆整合。

11.3 RAG 的关键不只是向量库

很多人把 RAG 简单理解为“向量数据库 + LLM”，但真正影响效果的是完整链路：

  • 文档解析质量；
  • 分块策略；
  • 嵌入模型；
  • 检索策略；
  • 重排序；
  • 上下文构建；
  • 生成提示词；
  • 引用和可解释性。

11.4 Memory 和 RAG 可以形成闭环

RAG 负责从外部知识库找资料，Memory 负责保存用户交互和学习过程。二者结合后，Agent 可以形成闭环：

这也是智能体从“工具调用系统”走向“长期智能助手”的关键。

12. 四类记忆对比表

记忆类型 生命周期 存储内容 技术实现 典型用途
工作记忆 短期 当前会话上下文 内存 + TTL 当前任务状态、多轮对话
情景记忆 中长期 具体事件和经历 SQLite + Qdrant 学习历史、交互记录
语义记忆 长期 抽象知识和规则 Qdrant + Neo4j 用户偏好、领域知识、概念关系
感知记忆 动态 多模态信息 多模态编码器 + 向量库 图片、音频、截图、跨模态检索

维度 Memory RAG
解决问题 记住历史和用户状态 利用外部知识回答问题
数据来源 用户交互、Agent 经验、个人偏好 文档、知识库、数据库、网页
信息特点 个性化、长期性、上下文相关 外部性、事实性、可引用
核心操作 添加、搜索、整合、遗忘 解析、分块、向量化、检索、生成
典型工具 MemoryTool RAGTool
适用场景 个人助手、学习助手、长期任务 文档问答、知识库问答、专业领域问答

14. 结语

第八章的核心价值在于说明：一个真正有用的 Agent，不应该只是会调用工具和生成回答，还应该能记住用户、积累经验，并从外部知识中获取依据。

Memory 让 Agent 具备连续性和个性化能力，RAG 让 Agent 具备知识更新和事实增强能力。二者结合后，Agent 才能从一次性问答系统升级为长期可用、可学习、可扩展的智能助手。

对于实际项目来说，本章的启发是：

  • 做个人助手时，要重点设计记忆类型、用户隔离和遗忘机制；
  • 做知识库问答时，要重点优化文档解析、分块和检索策略；
  • 做学习助手或科研助手时，要把 Memory 和 RAG 结合起来，既能查资料，也能记录用户的学习轨迹。
